# 圆屏健身记组

## 使用

桌面第二页打开「健身」。校时后首页按周一胸、周二背、周三肩、周四手臂、周五腿推荐计划，每日默认追加仰卧卷腹。周末默认休息，仍可手动选任意训练日。时间未同步时不推测日期，必须手动选日。

训练页的蓝色「完成一组」按钮只记录组数，目标次数不会被描述成实际完成次数。记组立即提交保存，进入组间休息；可暂停、继续、跳过或撤销上一组。完成动作后点击「下一动作」。最后一个动作的最后一组直接保存训练摘要、显示总结，不再计时。提前结束需在独立页面确认，未完成动作也保留在摘要里。已结束训练不支持撤销；进行中的撤销可跨越刚切换的动作，返回上一动作并只撤销最近一次记组。

「要点」展示单独文字页面，不覆盖动图和记组按钮。动图为原创关节运动简图，用于识别动作，并非个体训练指导。加载失败时显示静态示意，计组照常工作。

点击「桌面」或系统底部手势退出，不会结束训练；再次进入可继续。后台删除当前 GIF 解码器及其定时器，休息仍按单调时钟截止时间计算。回到前台只解码当前动作。关闭、暂停时保存剩余休息时间；突然断电恢复到最近一次成功保存的组数，休息一律暂停，等待点击「继续」。突然断电期间的休息时间不推算、不依赖未经同步的日期。

「设置」可分别调整全部 14 个动作的 1–10 组、目标 1–50 次，并选择 30/60/90/120/180 秒休息。默认 5 组 × 目标 12 次、90 秒。周计划模板支持更换、上移、添加、移除动作；每日至少 1 个、最多 4 个，不允许重复。设置立即保存，仅影响下一次开始的训练，已开始训练保留目标、动作顺序和休息时长快照。

「历史」按新到旧保留最近 30 次训练，每条包含开始日期、训练日、动作、已完成/目标组数、目标次数和完成状态。未同步时间时开始的训练始终标记「时间未同步」，即使稍后校时也不会补造开始日期。

## 持久化与故障

- 与网络设置隔离：NVS 命名空间 `fitness`，键 `state_v1`。
- 数据显式小端编码，有格式版本、长度、校验值和字段范围检查，不保存 C++ 对象内存或指针。
- 设置、当前训练、30 条摘要共一个 907 字节 blob，单次 `nvs_set_blob` + `nvs_commit` 提交，沿用原 24 KiB NVS、8 MiB 单应用分区，无 OTA 或分区变更。
- 只在状态改变及离开活动训练时写入；刷新倒计时不逐秒写入。未校时仍可训练及持久化。
- 写入失败不回滚内存进度，顶部显示「保存失败 · 点此重试」。点击重试会保存整个最新状态；失败期间不要断电，重启只能恢复最后成功保存的状态。
- 读取异常或校验失败显示同一存储异常提示，采用默认内存状态，不自动擦除 NVS 分区。重试保存/后续修改会写入默认状态和此后的进度；原损坏记录无法从应用恢复。

## 资源与代码

- `firmware/main/fitness_model.*`：无 LVGL/ESP-IDF 依赖的状态机和编码，可宿主测试。
- `fitness_storage.*`：独立 NVS 适配，不重新初始化 NVS。
- `fitness_view.*`：生产和预览共用页面、交互、GIF 生命周期。
- `fitness_app.*`：Brookesia 生命周期，沿用现有显示和触摸，不增加实体按键、传感器计数、重量输入或联网服务。
- `assets/fitness/`：14 个 GIF、首帧 PNG、SHA256 清单；`scripts/generate_fitness_assets.py` 可重现生成嵌入 C 文件。
- 动图 200×120、24 帧、2 秒一周期，以 80/80/90 毫秒序列近似 12 fps，避免 GIF 百分之一秒精度误差。RGB565 解码；100×60 静态示意放大两倍。
- 全套 GIF 和嵌入静态资源必须合计不超过 1 MiB；`verify_fitness_assets.py` 校验尺寸、帧数、时长、循环、哈希和容量。
- 原有全 CJK 中文字体已覆盖新增文本，宿主预览逐字检查，不另外嵌入重复字体。

## 验证和构建

在项目根目录运行：

```powershell
python scripts/generate_fitness_assets.py
python scripts/verify_fitness_assets.py
docker run --rm --mount "type=bind,source=$PWD,target=/work" -w /work espressif/idf:v5.5.3 bash scripts/test-fitness.sh
./scripts/preview-ui.ps1
./scripts/build.ps1
python scripts/verify_artifacts.py
```

`preview-ui.ps1` 构建生产页面的真实 LVGL 宿主预览，验证所有 GIF 循环解码、中文、圆屏触控边界、重复点击、存储/动图失败、设置和 100 次生命周期切换，并生成 `.cache/ui-preview/fitness-*.png`。预览中时间仅为固定测试数据。

常规 `build.ps1` 构建整个当前工作区。应用的 `Kconfig.projbuild` 自动选择 `LV_USE_GIF`，从旧 `sdkconfig` 升级时也会启用解码器；不必手工编辑菜单或擦除设备 NVS。

本次交付如果与其他功能并发开发，则验证产物单独放在 `dist/fitness/`，使用基线提交加健身文件的源码快照，不覆盖其他功能固件。具体版本、文件大小、命令及验证范围见 `FITNESS-VALIDATION.md`。USB 烧录作为后续步骤，不自动部署到实机。

## 尚需实机验收

- 原板连续切换 14 个动作、桌面和最近应用至少 30 分钟，确认内部 RAM/PSRAM 与 GIF 解码器不增长。
- 检查原板显示颜色、12 fps 动图流畅度、触摸目标、底部上滑及快速连点。
- 在记组、休息暂停、后台休息、设置变更和总结保存后断电，检查恢复与未校时显示。
- 填满 30 条历史后继续训练，确认轮换；验证真实 NVS 满/写入失败提示、恢复后重试。
- 编译及宿主测试不替代以上实机验证；本次没有 USB 烧录。
